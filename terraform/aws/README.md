# SiskelBot on AWS (ECS Fargate)

This Terraform module deploys SiskelBot to AWS as a containerized service on ECS Fargate, fronted by an Application Load Balancer, with optional RDS PostgreSQL and ElastiCache Redis.

## Architecture

```
Internet
   |
   v
Route 53 (optional)
   |
   v
Application Load Balancer  (public subnets, 2 AZs)
   |
   v
ECS Service (Fargate tasks, private subnets)
   |
   +---> RDS PostgreSQL (optional, private)
   +---> ElastiCache Redis (optional, private)
   +---> Secrets Manager
   +---> CloudWatch Logs
```

- 2-AZ VPC with public + private subnets
- NAT Gateway per AZ for outbound access from tasks
- ECS cluster with Container Insights enabled
- Fargate tasks in private subnets (no public IPs)
- ALB with HTTP listener (and HTTPS redirect when `certificate_arn` is set)
- Autoscaling on CPU (65%) and memory (75%)
- Secrets Manager for API keys, session secret, and connection strings
- IAM least-privilege execution role (secrets read + logs write)

## Quick start

```bash
cd terraform/aws

cat > terraform.tfvars <<EOF
aws_region      = "us-east-1"
environment     = "prod"
project_name    = "siskelbot"
container_image = "ghcr.io/your-org/siskelbot:latest"
desired_count   = 2
min_count       = 2
max_count       = 10

enable_postgres = true
enable_redis    = true

domain_name     = "chat.example.com"
route53_zone_id = "Z0123456789ABCDEFGHIJ"
certificate_arn = "arn:aws:acm:us-east-1:111122223333:certificate/abcd1234"

api_key        = "replace-me"
admin_api_key  = "replace-me"
session_secret = "replace-me-with-a-long-random-string"
openai_api_key = "sk-..."
EOF

terraform init
terraform plan -var-file=terraform.tfvars
terraform apply -var-file=terraform.tfvars
```

## Required inputs

| Variable | Description |
|----------|-------------|
| `container_image` | Docker image reference, e.g. `ghcr.io/org/siskelbot:sha` |
| `api_key` | Value for `API_KEY` env (protects `/v1/chat/completions`) |
| `admin_api_key` | Value for `ADMIN_API_KEY` env |
| `session_secret` | Value for `SESSION_SECRET` env (OAuth session cookies) |

## Optional components

- `enable_postgres = true` provisions RDS (db.t4g.micro by default). The task automatically receives `STORAGE_BACKEND=postgres` and a `DATABASE_URL`.
- `enable_redis = true` provisions ElastiCache Redis and injects `REDIS_URL`.
- `certificate_arn` enables HTTPS on port 443; HTTP traffic is redirected to HTTPS.
- `route53_zone_id` + `domain_name` creates an A alias pointing to the ALB.

| Component | Cost per month |
|-----------|---------------|
| ECS Fargate (2 tasks, 0.5 vCPU + 1 GB) | ~$30 |
| ALB | ~$18 |
| NAT Gateway (2) | ~$65 |
| CloudWatch Logs (5 GB) | ~$3 |
| RDS db.t4g.micro (optional) | ~$13 |
| ElastiCache cache.t4g.micro (optional) | ~$12 |
| **Minimum (no RDS/Redis)** | **~$116** |
| **Full stack** | **~$141** |

Data transfer, storage, and traffic are extra. Consider a single NAT gateway and VPC endpoints to cut cost for non-production environments.

## Security considerations

- All Fargate tasks run in private subnets; only the ALB is reachable from the internet.
- RDS and ElastiCache security groups only accept traffic from the ECS security group.
- Secrets are stored in Secrets Manager, injected as container env vars via the task definition, and never written to Terraform state in plaintext (but the RDS password is generated by `random_password` which is stored in state — protect your backend).
- Use a remote backend (S3 + DynamoDB) with encryption at rest and access controls.
- Rotate `api_key`, `admin_api_key`, and `session_secret` by updating the Secrets Manager version and redeploying tasks.
- Enable AWS WAF on the ALB for production workloads.

## Upgrading

1. Build and push a new container image.
2. Update `container_image` in `terraform.tfvars`.
3. `terraform apply` — ECS performs a rolling update (min 50% healthy, max 200%).

To roll back, set `container_image` to the previous tag and re-apply.

## Outputs

| Output | Description |
|--------|-------------|
| `alb_dns_name` | DNS name of the load balancer |
| `public_url` | Full URL (uses custom domain if configured) |
| `ecs_cluster_arn` | Cluster ARN for kubectl-like CLIs |
| `rds_endpoint` | RDS address (null if disabled) |
| `redis_endpoint` | Redis address (null if disabled) |
| `log_group_name` | CloudWatch log group name |

## Tearing down

```bash
terraform destroy -var-file=terraform.tfvars
```

Set `environment = "dev"` to skip final RDS snapshots and disable deletion protection, or manually disable them before destroying.
