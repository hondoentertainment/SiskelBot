# Postman Collection

A Postman Collection v2.1 is generated from the SiskelBot OpenAPI spec so you can
explore and exercise the API from Postman, Insomnia, Hoppscotch, or any other
tool that imports the standard collection format.

## Where to find the collection

The committed file lives at:

```
postman/SiskelBot.postman_collection.json
```

It is grouped into folders by OpenAPI tag (e.g. `chat`, `conversations`,
`webhooks`, `admin`). Each request includes:

- A pre-filled URL that uses `{{baseUrl}}`
- An `Authorization: Bearer {{apiKey}}` header
- A JSON body example synthesized from the request schema (where applicable)
- Path and query parameters described inline

## Importing

### Postman

1. Open Postman.
2. Click **File -> Import** (or use the `Import` button in the sidebar).
3. Select `postman/SiskelBot.postman_collection.json`.
4. Open the collection's **Variables** tab and set:
   - `baseUrl` (e.g. `http://localhost:3000` or your deployed origin)
   - `apiKey` (a SiskelBot user API key or deployment API key)

### Insomnia

1. **Application -> Preferences -> Data -> Import Data -> From File**.
2. Choose `postman/SiskelBot.postman_collection.json`.
3. Set `baseUrl` and `apiKey` in your environment.

### Hoppscotch

1. Open the **Collections** panel.
2. Click **Import** and select **Postman Collection v2 / v2.1**.
3. Upload `postman/SiskelBot.postman_collection.json`.
4. Set `baseUrl` and `apiKey` as environment variables.

## Regenerating the collection

The collection is generated by
[`scripts/openapi-to-postman.mjs`](../scripts/openapi-to-postman.mjs) from the
OpenAPI spec at `docs/openapi.yaml`.

### Manual

```bash
npm run postman:generate
```

This regenerates the OpenAPI source first (`npm run openapi:generate`) and then
converts it to the Postman collection.

### Automated

`.github/workflows/postman.yml` regenerates the collection on every push to
`main` / `master` when any of these change:

- `lib/openapi-spec.js`
- `lib/openapi-overrides.js`
- `routes/**`
- `scripts/openapi-to-postman.mjs`
- `scripts/generate-openapi.mjs`
- `docs/openapi.yaml`

If the regenerated file differs from what is committed, the workflow opens a PR
on branch `chore/refresh-postman` so the change can be reviewed and merged.

## Direct usage from the CLI

You can also invoke the converter directly against any OpenAPI input
(YAML or JSON):

```bash
node scripts/openapi-to-postman.mjs \
  --input=docs/openapi.yaml \
  --output=postman/SiskelBot.postman_collection.json \
  --name="SiskelBot"
```

Supported flags:

| Flag | Description |
|---|---|
| `--input` | Path to the OpenAPI spec (`.yaml`, `.yml`, or `.json`) |
| `--output` | Path for the generated Postman collection |
| `--name`  | Optional collection name (default: `SiskelBot`) |
